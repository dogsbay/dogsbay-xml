# Changelog

All notable changes to DogsBay XML are documented here. The format is based on
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project aims
to follow [Semantic Versioning](https://semver.org/) once it reaches 1.0.

## [Unreleased]

### Removed
- **The repository carries what it takes to build.** `docs/`, `docs-dev/` and
  `plans/` are no longer tracked: the user documentation lives on the website
  and the rest is working material. `loader.properties` is generated by
  `syncLib`, so it is no longer committed either. A dead `scripts/makeBrowserView`
  went with the JDIC and BSF jars it depended on.
- **JavaHelp.** Help ▸ Contents, Index, Search and Getting Started read a help
  set (`help/DogsBayHelp.hs`) that is not shipped, so all four were permanently
  disabled and the editor logged a parse failure on every start. The menu now
  has a single **Documentation** item that opens the website, and `lib/jh.jar`
  and its wiring are gone.
- **17 unused jars** dropped from `lib/`: JCalendar, MDateSelector, Kunststoff,
  JGoodies Looks, JDIC, JISP, BSF, JavaMail with its activation jar, XMLBeans,
  jsr305, an ancient `jaxp.jar` shadowing the JDK's own `javax.xml.parsers`,
  and the SOAP stack (SAAJ, SOAP, WSDL4J) whose support had already been
  removed from the classpath, one of which was a corrupt zip.

### Changed
- **The demo corpus has its own repository**, `dogsbay-xml-dita-tutorial`, copied
  from the private `agent-initial-content` without its history so it can be
  published. The bundled sample project, the `bundleDemo` task and the
  end-to-end workflow all read from it. Once it is public, the fork guard and
  the token on that workflow's checkout can go, and forks get to run the
  end-to-end assertions too.
- **`loader.properties` is generated** by `./gradlew syncLib` from what is
  actually in `lib/`. Hand-maintained, it had drifted into naming 17 jars that
  no longer exist while missing every one since added.

### Fixed
- **The update check polls the right repository.** It asked GitHub for the
  latest release of `dogsbay/dogsbayxml`, the predecessor of this repository,
  so a released build would have compared itself against another project's
  versions. It now asks for `dogsbay/dogsbay-xml`.
- **Schematron at the current release.** ph-schematron moves from 8.0.6 to
  10.0.2, which also replaces ph-commons 11.2.0 with the 12.4.0 split
  artifacts. Running a schema no longer prints a warning and a stack trace
  about XXE protection: the JDK's schema factory is pinned for the run, so
  the protection is applied rather than skipped.
- **RelaxNG at one current version.** Jing and Trang move to the 20241231
  release and come from Maven rather than from jars committed to `lib/`, one
  of which carried no version at all. Absorbing xagent had left two Jings on
  the classpath at once, the vendored one and the agent's, which is the kind
  of thing that decides which class wins by accident.
- **Switching views keeps your place.** Going from the Author view to the XML
  source put the caret wherever the XML view was last, usually the top of the
  file; it now lands on the block you were editing, and coming back selects
  the block the caret was in.
- **Author view opens real-world topics.** A topic with the standard
  `xmlns:ditaarch` header, which Oxygen and DITA-OT write on every file,
  was refused by the Author view; namespace declarations and namespaced
  attributes now round-trip. A plain `<ph>` around text was silently dropped
  on save; it is kept. Author edits made through commands now reach the
  Editor pane and the file on disk, and a failure to apply the view's edits
  is reported instead of silently saving stale text.
- **The first terminal opens in the project.** It used to be created at
  startup, before any project was open, so it always started in the home
  directory; later terminals started in the project. It is now created when
  the Terminal tab is first shown and starts in the project folder, else the
  folder open in the File Explorer, else the current document's folder.
- **Bookmaps validate again.** The bundled DITA 1.3 DTD set lacked the XNAL
  domain that `bookmap.dtd` pulls in, so every bookmap failed with a missing
  `xnalDomain.ent`. The two files and their catalog entries are bundled; the
  built-in assets refresh on next start.
- **CLI paths and noise.** Project-scoped commands normalise the root, so a
  `.` argument no longer prints `/./` in every path; the duplicate SLF4J
  provider that made the CLI warn on every start is excluded.

### Added
- **xagent is part of this repository.** The embeddable agent library and its
  CLI, previously the separate `dogsbay/xagent`, are now the `xagent-core`
  and `xagent-cli` modules of this build, relicensed under this project's
  Apache 2.0 licence (they carried no licence file before). The editor builds
  against the source directly, so the vendored agent jar, the nine vendored
  langchain4j jars, the private checkout in two workflows and the CI step
  that compared two jars' public APIs are all gone. Every dependency the
  modules share now resolves to one version, the later of the two.
- **Author view polish.** Undo is shared by the Author and XML views: undoing
  an Author edit updates the XML pane and the other way round. Whole blocks
  cut, copy, paste and duplicate as XML, so they travel to the XML view or
  another application. Bulleted lists convert to numbered and back. The
  prolog is editable rather than an XML chip, with author, source,
  copyright, critical dates, permissions and metadata as blocks.
  `xml:space="preserve"` is honoured on any block or its ancestors, not only
  in code blocks. A spanning table cell names its span in its header. The
  validator adds duplicate ids, definition entries missing a term or
  description, links without a target, span-aware row widths and column
  counts that disagree with the column definitions. Ctrl+Plus, Ctrl+Minus
  and Ctrl+0 scale the text, remembered between sessions, keeping the caret
  where it was. An index hierarchy (an `indexterm` inside an `indexterm`) is
  kept verbatim instead of being flattened, in the body as well as the
  prolog, and saving no longer re-indents inside `xml:space="preserve"`.
- **Author view editing.** Cut, copy and paste keep inline markup; an
  Insert Link button makes the selection an xref by href or key; inserting
  an image opens a file chooser and stores a topic-relative path; CALS
  tables get row and column operations with the column count and
  definitions kept in step; Enter on an empty last list item leaves the
  list; Up and Down move between blocks at their edges, Ctrl+Home and
  Ctrl+End to the document's ends; the standalone app has Undo and Redo.
  Structural edits redraw only the blocks they add, attribute edits redraw
  their block, clicking an outline entry scrolls to the right place, and a
  split-view refresh keeps your place and selection. An edit the content
  model refuses is reported in the breadcrumb line instead of failing
  silently, and a file that already breaks its model stays editable. Column
  operations refuse a table with spanned cells rather than corrupt it, and
  a new column never reuses an existing column name. A submap edit
  invalidates the cached key space.
- **Author view covers the DITA 1.3 vocabulary.** Troubleshooting and
  glossary-group topics; divisions, syntax sections, unordered and informal
  steps, step examples, choice tables, quotes, simple and parameter lists,
  preformatted text, screens, message blocks, hazard statements and draft
  comments are editable blocks rather than raw chips; a CALS table directly
  in a reference body is too. Every DITA inline element is a styled run,
  nested inlines such as a menu cascade of controls included, with their
  attributes kept. The insert menu follows the content model's order and
  counts, so it never offers a second title or steps before prerequisites,
  and a generated table has a column count and a column definition.
- **Send selection to AI Agent.** Select text in an editor tab, a rendered
  preview, or the Terminal and right-click: it runs as a prompt in the agent tab in front,
  hosted or built-in, so tutorial commands need no copying.
- **Drag topics and maps out of the DITA explorer**, the same way as files
  from the File Explorer, so a topic from the map tree can be dropped on an
  agent chat box to mention it.
- **The built-in AI Agent catches up with the hosted tabs.** Multi-line
  prompts with Shift+Enter, completion of its slash commands as you type,
  a dot on its tab when a turn ends out of view, and Export or Copy
  transcript from the tab's right-click menu.
- **Drop files on the built-in AI Agent too.** A file dragged onto its box
  becomes an `@path` mention and its text goes with the prompt; the box
  used to take the raw path and read it as a slash command.
- **Drag files out of the File Explorer.** Selected files drag as a file
  list, so they can be dropped on an agent chat box to mention them, or on
  anything else that takes files.
- **Chat polish for hosted agents.** Multi-line prompts (Shift+Enter),
  slash-command completion from the agent's own command list, drop a
  project file onto the box to mention it, a dot on a tab whose agent
  finished a turn while out of view, and Resume for the last eight
  conversations per agent instead of one.
- **Rename and export hosted agent sessions.** Double-click a tab or use its
  right-click menu to name a session; the name follows it into Resume. The
  same menu exports the transcript as Markdown or copies it.
- **Resume a hosted agent's conversation.** The + menu offers Resume under
  an installed agent when it had a session in this project; the agent
  replays the earlier conversation and continues with it.
- **Install binary agents from the editor.** Install an agent in the +
  menu downloads a registry agent that ships as an archive, such as
  OpenCode or goose, into `~/.dogsbay/agents`, checks the registry's
  checksum and starts it. Nothing is added to the PATH.
- **`audit-log` command.** What agents did in a project, newest first, from
  the CLI without the editor, over JSON-RPC, and as the `agent_audit_log`
  tool so agents can see each other's changes.
- **Show changes in the preview.** A toolbar tick on the preview, the
  `--show-changes` flag of `preview`, and `showChanges` on the
  `render_preview` tool draw open review proposals in the rendered page:
  insertions green, deletions red and struck, changed elements amber, and
  comments as notes with the author's identity.
- **Agent replies render as Markdown.** In the hosted agent tabs and the
  built-in AI Agent, a reply streams as it arrives and, once complete, is
  shown with headings, bold and italic, code, lists, quotes, links with
  their targets, and tables, instead of raw Markdown.
- **Contiguous word changes are one proposal.** A run of changed words
  with only spaces between them, such as a number and its unit, is one
  delete and one insert instead of independent pairs that make no sense
  accepted alone. An unchanged word ends the run; inside code blocks and
  other preformatted elements, so does a line break.
- **Proposals stay out of published output.** The preview (View → Preview in
  Tab or Split) renders a document with open review proposals as if they
  were accepted.
  Builds and deep validation add a generated DITAVAL that excludes struck
  text, and the project health report lists files with open proposals,
  their counts and authors.
- **Agent sessions.** Every caller of the command engine is now an identified
  session: the user, the built-in AI Agent, and each external MCP or JSON-RPC
  client. MCP clients are named from their `initialize` handshake and get a
  `Mcp-Session-Id` they echo on later calls; the integration server accepts
  per-session bearer tokens alongside the master token. Commands that can
  change something, run by an agent, are appended to
  `.dogsbay/agent-audit/commands.jsonl` with the agent's identity, the files
  involved, whether it was a dry run, and the outcome. Groundwork for hosting
  Agent Client Protocol agents; see `docs-dev/agent-sessions.md`.
- **Review and session commands.** `review-list`, `review-accept`,
  `review-reject` and `review-comment` on the CLI (`dogsbay-xml review …`), over
  JSON-RPC, and as the MCP tools `review_list` and `review_comment` for
  agents, who may list and comment but never decide. In the editor they act
  on the open buffer as one undo step; on the CLI, on the file. `sessions`
  and `agents` list the connected agent sessions and the runnable registry
  agents (`dogsbay-xml sessions`, `dogsbay-xml agents`, MCP `list_agent_sessions`).
- **Agent edits land as proposals.** When any agent, built-in, hosted or
  external, edits a DITA document through `set_document_content` or
  `replace_selection`, the change is marked rather than applied:
  insertions as `status="new"`, removals kept as `status="deleted"`, with
  the agent's identity in `rev`, all valid DITA. The Editor view tints them,
  a new **Proposals** sidebar lists them, and Accept or Reject, per change or
  per agent, is one undo step recorded in `.dogsbay/agent-audit/review.jsonl`.
  A write that would erase another author's open proposals is refused. Off
  switch in Preferences → Server. Author-view edits and the refactorings still
  apply directly. The `com.dogsbay.xml.review` package
  behind it works by textual splices into the source, never a DOM
  re-serialise, and proves that accepting everything reproduces the agent's
  text and rejecting everything reproduces the original. See
  `docs/agent-proposals.md` and `docs-dev/review-model.md`.
- **Hosted agents in the AI Agent sidebar.** The sidebar is now tabbed: `+`
  lists the Agent Client Protocol registry agents installed on this machine
  (Claude Code, Codex, Gemini CLI, goose, …) and opens one in its own tab, at a
  tier you choose: commands only, read files, or read and write files. The
  agent keeps its own login, gets the editor's DITA tools over MCP as its own
  attributed session, asks its permission questions in the editor, and can
  follow the files it edits. `@path` in a message attaches a project file. An
  API key saved for the built-in agent can be passed to a hosted agent of the
  same vendor, opt-in per session. The
  status bar shows how many agent sessions are connected. **Project → Agent
  activity…** shows the audit log as a table, and the File Explorer can now
  show hidden files and folders. See `docs/hosted-agents.md`.
- **Agent Client Protocol client.** The editor can now
  spawn any agent from the ACP registry (Claude Code, Codex, Gemini CLI, goose
  and others), drive it over stdio, answer its permission prompts, serve its
  file reads from unsaved buffers and route its writes through the document
  model, and hand it the editor's MCP tools with the session's own token. A
  stdio bridge covers agents that only speak stdio MCP. Verified against the
  real Claude adapter. See `docs-dev/agent-sessions.md`.
- **A write gate for agents.** Every command from an agent that can change
  something now passes three checks: external clients may only write inside
  the open project; one agent at a time may edit a document (a chat agent
  holds it until its turn ends, an external client for ninety seconds); and a
  buffer edit must follow a read of that document (content or outline) and be
  refused, with the current content, if the document changed in between. The
  `dogsbay` CLI on the master token runs as you and is not gated. Refusals carry the new
  `CONFLICT` and `LOCKED` error codes. MCP `tools/list` now marks read-only
  tools with `readOnlyHint`, and the built-in agent's approval prompts, the
  MCP hint, the gate and the audit log all read one declaration per command.

### Changed
- **The text editor's view layer now builds on the public Swing API.** The
  editor's line rendering, soft wrapping and code folding were previously built
  on forks of internal `javax.swing.text` classes frozen at their 2002 versions.
  They are now genuine subclasses of the public `PlainView`, `WrappedPlainView`
  and `GapContent`.
  - **Visible improvement:** text now renders through Swing's current layout
    path, which positions glyphs with fractional precision on high-DPI displays;
    the 2002 forks only had the integer path.
  - Code folding behaves as before. Two long-standing defects were fixed in
    passing: collapsing a fold could leave the view laid out at its old
    positions, and every `Position` created for a document leaked until it was
    closed.
  - Collapsing a fold with soft wrapping on no longer draws the hidden lines on
    top of one another at the fold boundary.

### Added
- **`schematron`** — apply a Schematron schema to a single document, from
  **Project ▸ Validate ▸ Document with Schematron…**, the CLI
  (`dogsbay-xml schematron file.dita rules.sch`), MCP or JSON-RPC. The document-scoped
  peer of `schematron-project`, sharing its engine and results.
- **Caret and element-selection commands** in the command engine, reachable from the
  CLI, MCP and JSON-RPC: `goto-line`, `cursor` (show, `--set`, `--move`) and
  `select-element` (`--content`). These existed only in the JavaScript scripting
  API before, so they were the one editor capability missing from the CLI/API.
  `cursor` reports offset plus 1-based line and column; `goto-line` rejects an
  out-of-range line rather than silently parking the caret at the end.

### Removed
- **JavaHelp.** Help ▸ Contents, Index, Search and Getting Started read a help
  set (`help/DogsBayHelp.hs`) that is not shipped, so all four were permanently
  disabled and the editor logged a parse failure on every start. The menu now
  has one **Documentation** item that opens the website, and `lib/jh.jar` and
  its wiring are gone.
- **The legacy Schematron implementation** — Transform ▸ Scenario ▸ Execute
  Schematron, its dialog, its trace/message plumbing, and the 11 bundled ISO
  Schematron XSL skeletons across three generations, two of them Schematron 1.5.
  - Schematron validation is unaffected: use **Project ▸ Validate ▸ Project with
    Schematron**, `dogsbay-xml schematron-project`, or the new `dogsbay-xml schematron`
    for a single document. All run the same ph-schematron engine.
  - **Only ISO Schematron is supported.** A pre-ISO Schematron 1.5 schema (the
    `http://www.ascc.net/xml/schematron` namespace) is now rejected as invalid.
  - `NOTICE` no longer needs the ISO Schematron attribution; XDiff is the only
    third-party source left in the tree.
- **The JavaScript scripting subsystem** — the Scripting tab in the output panel,
  Tools ▸ Execute Script, the `DogsBayApi` script binding, the bundled Rhino
  interpreter (`lib/js.jar`) and the sample scripts.
  - **Why:** the vendored Rhino source had been repackaged with its Mozilla Public
    License headers stripped, which the MPL does not permit and which blocked the
    Apache-2.0 release. The feature was also long dead: the jar dates to 2008, the
    scripts address the editor by its pre-rename `exchanger` name, and the sandbox
    was built on `SecurityManager` — permanently disabled in JDK 24, so scripts ran
    fully privileged.
  - **Nothing was lost from the CLI/API**: the caret and element-selection calls it
    uniquely offered were ported into the command engine first (see Added).
  - `selectNode(Node)` has no replacement; it took a live in-process DOM node. Use
    the `query` command's XPath instead.
- **XML Schema (XSD) editing support**, and Apache Castor with it. DITA and DocBook
  are DTD/RelaxNG-based, so the XSD object model earned nothing. Removed: the
  Castor-backed schema model (`XMLSchema`, `SchemaModel`, `SchemaElement`,
  `SchemaType`, and friends), the Schema Viewer, the schema generation and
  conversion dialogs, and XSD as a tag-completion grammar.
  - **Tag prompting is unaffected for DTD and RelaxNG.** `SchemaDocument` has
    three implementations; only the XSD one is gone, and completion consumes the
    grammar-neutral `ElementInformation` either way.
  - **XSD validation still works** — it runs through Xerces, never Castor. An
    XSD-associated document validates exactly as before; it simply gets no tag
    prompting, silently.
  - The Author view's generic-XML mode now infers block structure from the
    document instead of from an XSD; that fallback already existed.
- **The Designer ("Outliner") view.** It was unreachable — `switchToDesigner()`
  dereferenced a navigation button that nothing ever set, so it would have thrown
  a `NullPointerException` had any menu offered it.
- **SOAP and WSDL support** — the web-service dialogs, client, and WSDL parser.
- Apache Xalan (`xalan.jar`, `serializer.jar`) and every XSLT-processor choice
  that went with it. **Saxon-HE 12.7 is now the only XSLT processor.** The
  "Default XSLT Processor" panel is gone from Preferences, the Xalan option is
  gone from the scenario, Execute-XSLT and XSLT-processor dialogs, and the
  `PROCESSOR_XALAN` scenario type and `DogsBayApi.XSLT_PROCESSOR_XALAN` id are
  removed. The WSDL and SOAP dialogs no longer force the Xalan factory. This
  retires CVE-2022-34169 and an incomplete vendored jar that was missing
  `org.apache.xpath.compiler.FuncLoader`.
- Apache Batik (19 vendored jars, ~4.9 MB) and the SVG viewer/converter code that
  used it — `SVGViewerDialog`, `ConvertSVGDialog`, `OpenSVGAction`,
  `ConvertSVGAction` and their key mappings, ~3,500 lines. Nothing added these
  actions to a menu or toolbar, so no reachable feature is lost. This also
  removes Batik's SVG-driven SSRF/XXE CVE exposure and the "error reading
  lib/batik-*.jar" messages that appeared on every build.
  - **Known consequence:** the vendored Apache FOP 0.20.5 relied on Batik for
    SVG inside XSL-FO. PDF output from XSLT scenarios still works for content
    without SVG; SVG-in-PDF will fail until the PDF path is reworked. DITA-OT
    PDF publishing is unaffected — it ships its own FOP and Batik.

### Fixed
- **The build compiles again from a clean checkout.** `lib/saaj-impl.jar` is a
  corrupt zip that `javac` refuses to read, which failed every compile while it
  was on the classpath. The SOAP, SAAJ and WSDL jars were dead since that
  feature was removed and are no longer referenced by the build; the files
  remain in `lib/` pending removal.
- **Saving no longer discards your edits.** `save()` writes the document model,
  and the method that pushes the editor's text into that model had been emptied,
  so every save wrote the last parsed state — silently losing everything typed
  since. Introduced while retiring XML Schema support; not present in any
  released build.
- **Open documents no longer go stale after an external change.** Reloading
  refreshed the document model but never pushed it into the view, so a file
  changed on disk — by an AI agent turn, a Git discard/stash/checkout/pull, the
  map or reltable editors, or File ▸ Reload — kept displaying its previous
  content, and the next save wrote that stale buffer back over the change. The
  visible view is now refreshed on every reload path.
  - Also fixed for Markdown, AsciiDoc and plain text, and for XML that is
    momentarily malformed on disk: the reload aborted before refreshing anything
    for those, because the parse failure was treated as a failed read.
  - A buffer with unsaved edits no longer loses the external-change signal. The
    check that detects it is one-shot, so testing it before deciding to skip a
    dirty buffer meant the promised "ask on tab focus" prompt never appeared.
- Clicking a validation result reported without a column (Schematron and the
  DITA project rules) put the caret on the *previous* line — two lines back when
  the line between was blank. Those rows now show `Ln N` alone rather than an
  internal `Col -1`.
- Project Validation rows no longer lose their filename when their file is
  opened. Clicking one row blanked the name on every row from that same file.
- Closing a document whose close-time save fails no longer discards unsaved
  edits — the document stays open and its prior location is restored.
- Local document saves are now atomic (write to a temp file, then rename), so a
  failed save can never truncate the previously-good file.
- Find/replace-in-files preserves each file's encoding, line endings, and
  trailing-newline state, and writes atomically.
- Reloading a document whose on-disk copy became unreadable no longer silently
  discards the in-editor buffer; the failure is reported and the buffer kept.
- Preferences/session are saved atomically and under a lock, preventing a
  corrupted `~/.dogsbay-v33.xml` from a crash or a background/foreground race.

### Security
- Removed the end-of-life `commons-httpclient` 3.x (CVE-2012-5783: no TLS
  hostname verification) and the defunct `jakarta-slide-webdav`. Remote
  http/https document open/save now uses the JDK `java.net.http` client, which
  verifies TLS certificate hostnames by default.
- Removed the XML digital-signature/canonicalization feature and its abandoned
  Apache Santuario (`xmlsec`) dependency.
- XML parsing and transformation are hardened against XXE/SSRF: external
  entities and external DTD/stylesheet access are disabled while DITA catalog
  resolution is preserved (`com.dogsbay.xml.SecureXml`).
- The embedded HTTP server now compares its bearer token in constant time,
  validates `Host`/`Origin` (DNS-rebinding defense), and creates its token and
  discovery files owner-only from the moment of creation.

### Changed
- The startup update check can be disabled (`update-check-enabled` preference)
  and is documented in SECURITY.md.
